# 28 — Glossary and Terms

---

## 1. Domain and commerce

| Term | Meaning |
|---|---|
| **Variant** | A purchasable size/colour combination of a product. One `products` row maps to many `product_varient` rows. Spelled `varient` throughout this codebase |
| **SKU** | Stock-keeping unit — the courier-facing code in `productstocks.sku`, unique per variant × warehouse combination |
| **Cart line** | One row in `carts`: a variant plus a quantity. Distinct from a cart |
| **Cart** | The set of cart lines for one user (`user_id`) or guest (`ip_addresscart`) |
| **Wishlist** | Saved variants, one row per product × variant |
| **Guest token** | Intended identifier for an anonymous shopper's cart. **Four read sites, zero write sites** |
| **GST** | Goods and Services Tax. 5% applied at `CheckoutController.php:196-201` |
| **IGST** | Interstate GST, also 5% here, applied when billing and shipping states differ |
| **MRP** | Maximum retail price — `productstocksprices.mrp_price` |
| **Sale price** | The price actually charged, `offer_price` |
| **AWB** | Airway bill — the courier tracking number. Generated by Shiprocket, stored as `shiprocket_awb` |
| **Pickup** | The physical collection event where the courier takes the parcel. Shiprocket calls it `createPickup`; **never invoked** |
| **Manifest** | A batch of orders uploaded to Shiprocket for dispatch |
| **RTO** | Return to origin — an undelivered parcel returned to the seller |
| **Razorpay order** | The upstream payment intent, created by `preparePayment()`. Distinct from a local `product_orders` row |
| **Checkout / place-order** | The endpoint that captures payment and persists the order. Currently failing |
| **Thank-you page** | `GET /checkout/thankyou/{order}` — confirmation screen |
| **Reconciliation** | Comparing captured payments against persisted orders. **Not implemented** |
| **Idempotency** | Guaranteeing a retried request produces one effect, not many. Not implemented on `place-order` |
| **Coupon** | Discount rule. `coupons` table exists; engine absent; `hidden_coupon_discount` hard-coded `0` |

## 2. Stack and framework

| Term | Meaning |
|---|---|
| **Laravel 12** | Framework. PHP 8.2, no legacy scaffolding |
| **Blade** | Templating engine. Every page is a `.blade.php` view |
| **Eloquent** | Laravel's ORM. 24 models, 24 tables |
| **Form Request** | A dedicated validation class in `app/Http/Requests/`. **None exist** |
| **Middleware** | Request pipeline stage. Only Laravel's defaults are in use |
| **Artisan** | Laravel's CLI |
| **Route model binding** | Injecting a model from a `{param}`. Used on `{order}` and `{address}` **without ownership scoping** |
| **CSRF** | Cross-site request forgery protection. Active on all `POST`/`PUT`/`DELETE` |
| **`419`** | The CSRF-expiry status code. Handled in 1 of 32 `fetch()` calls |
| **Vite** | Frontend build tool. Configured in `vite.config.js`; **unused** |
| **Tailwind CSS** | Utility CSS framework. Configured; **unused** |
| **MarketPro** | The purchased HTML template behind the Blade markup |
| **jQuery** | Loaded twice — 3.7.1 locally and 3.6.0 from a CDN |
| **AJAX / `fetch`** | 32 calls, all inline in Blade |
| **`composer run dev`** | Runs `npm run dev` **and** `queue:listen` in parallel |
| **Config cache** | `php artisan config:cache`. Makes `env()` outside `config/` return `null` |

## 3. Integrations

| Term | Meaning |
|---|---|
| **Razorpay** | Indian payment gateway. SDK physically in `vendor/` but **absent from `composer.lock`** |
| **`Razorpay\Api\Api`** | SDK entry class. `require_once`'d inline because it is not autoloadable |
| **`checkout.js`** | Razorpay's browser script, loaded by CDN in `checkout.blade.php` |
| **`compareChecksum`** | Razorpay's HMAC signature comparison. Proves the response is genuine; does **not** verify the amount |
| **`RazorpayCheckout`** | Browser object opened by `checkout.js` to collect payment |
| **Shiprocket** | Indian shipping aggregator. 11 methods, **4 used** |
| **Bearer token** | Shiprocket's auth token, cached 8 hours |
| **`getToken()`** | Authenticates against Shiprocket and caches the token |
| **Shipping services / couriers** | Available options returned by `get-couriers`, priced per weight and pincode |
| **Billing vs shipping address** | Charge address vs delivery address. Both required on checkout |
| **`MAIN_URL`** | Base URL of the image host, read via `env()` in `SearchController.php:29` |

## 4. Environment and operations

| Term | Meaning |
|---|---|
| **`.env`** | Local environment file, git-ignored. 66 keys, incl. 8 absent from `.env.example` |
| **`.env.example`** | Template for new setups. **Missing all commerce keys** |
| **`APP_DEBUG=true`** | Full stack traces rendered in the browser. **Must be `false` in production** |
| **XAMPP** | The local Apache/MySQL stack this project runs under |
| **`palvarnan_db`** | MySQL database, **shared with `palVarnanDashboard`** |
| **`palVarnanDashboard`** | The sibling admin application. Owns ≈57 domain migrations |
| **Schema drift** | The gap between migrations, the SQL dump, and the live database |
| **Manual migration** | An `ALTER TABLE` applied by hand. 3 columns exist this way |
| **`php artisan serve`** | PHP's built-in server on port 8000 |
| **Scheduler** | `routes/console.php` — stock Laravel, **no scheduled tasks** |
| **`session:prune`** | Deletes expired session files. **Never scheduled** |
| **Single log channel** | One unbounded `laravel.log`, no rotation, no alerting |
| **Test script** | `test_apis.php` / `test_services.php` — **not tests**. Live credentials, TLS verification disabled, can mutate schema |

## 5. Schema naming quirks

### 5.1 Misspellings

| Written | Intended | Where |
|---|---|---|
| `product_varient` | `product_variant` | table name, ~24 model files |
| `varient` | `variant` | `product_varient.varient` |
| `product_varient_id` | `product_variant_id` | `carts`, `wishlists`, `product_slots` |
| `product_variant_id` | — | `product_order_items` (**inconsistent**) |
| `pro_ver_id` | `product_varient_id` | `productstocks` |
| `pro_var_id` | `product_varient_id` | `productstocksprices`, `product_varient_pictures` |
| `ip_addresscart` | `ip_address_cart` | `carts`, `wishlists` |
| `availablestock` | `available_stock` | `productstocks` |
| `salestock` | `sale_stock` | `productstocks` |
| `low_stocks` | `low_stock` | `productstocks` |
| `boostrap.bundle.min.js` | `bootstrap…` | filename |
| `productvari()` | `variants()` | `Product` relationship |
| `categoryid` | `category_id` | `product_varient` |

**Do not rename in place.** The blast radius spans the schema, 24 models, two applications, and the dashboard's 57 migrations. Document and normalise going forward.

### 5.2 Columns referenced but absent

| Column | Referenced at | Consequence |
|---|---|---|
| `products.product_price` | `CheckoutController.php:60,182,279,367`, `ProfileController.php:88` | chain falls through to `offer_price ?? 0` |
| `product_orders.billing_state` | `CheckoutController.php:296` | **checkout fails** |
| `product_orders.shipping_state` | `CheckoutController.php:297` | **checkout fails** |
| `product_order_items.product_image` | `CheckoutController.php:318` | **checkout fails** |
| `sub_categories.category_id` | `SubCategory::category()` | `Unknown column` in the log |
| `brands.slug` | `SearchController.php:83` | `/brand/` |
| `categories.slug` | `SearchController.php:103` | `/category/` |

### 5.3 `$fillable` columns silently stripped

| Column | Reason |
|---|---|
| `carts.pre_order`, `carts.pre_note` | absent from `Cart::$fillable` |
| `product_varient.flash_sale`, `.flash_sale_date`, `.hot_deals` | absent from `ProductVarient::$fillable` |
| `product_orders.pickup_scheduled` | present in `$fillable`, never assigned |
| `product_orders.created_at`, `.updated_at` | present in `$fillable` — forgeable |

### 5.4 Country encoding

| Column | Type | Meaning |
|---|---|---|
| `products.country_id` | `int` | one country, `NULL` for global |
| `categories.country_id` | `varchar` CSV | `"1,2,4"` |
| `brands.country_id` | `varchar` CSV | `"1,2,4"` |

Hence `FIND_IN_SET(?, country_id)` at 4 sites — unindexable by construction.

## 8. Status vocabulary

| Term | Definition |
|---|---|
| **VERIFIED** | Read directly from source, or confirmed in `storage/logs/laravel.log`, with a file and line reference |
| **INCOMPLETE** | Implemented but non-functional, or functional only in part of the flow |
| **BROKEN** | Confirmed non-functional, or would fail on a clean deploy |
| **UNVERIFIED** | Not determinable from the artefacts available — stated rather than guessed |
| **P0** | Blocks revenue, leaks money, or compromises an account |
| **P1** | Correctness, security, or deployability |
| **P2** | Performance, maintainability, or correctness at volume |
| **P3** | Cosmetic or hygiene |
| **S1** | Critical: money loss, data loss, or account compromise |
| **S2** | High: exploitable or revenue-blocking |
| **S3** | Medium: functional defect or notable debt |
| **S4** | Low: hygiene, dead code, or cosmetic |
