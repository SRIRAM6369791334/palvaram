# palVarnanDashboard — Audit Documentation

Read-only knowledge base for the Laravel admin/customer dashboard located at
`C:\xampp\htdocs\pauls\palVarnanDashboard`.

Generated by static source analysis. **No application source, configuration, schema, or dependency
was modified during this audit.**

## How to read these documents

Every finding carries one of four status labels:

| Label | Meaning |
| --- | --- |
| `VERIFIED` | Directly observed in a file at the cited path/line. |
| `INCOMPLETE` | Code exists but is partial, stubbed, or unreachable. |
| `BROKEN` | Code is internally inconsistent, references missing symbols, or is dead. |
| `UNVERIFIED` | Inferred but not confirmable without running the app or database. |

Secrets are never reproduced. They appear only as `[SECRET_REDACTED]`.

## Headline findings

- `BROKEN` — Two routes call methods that do not exist (`SubCategoryController::validateSubCategoryName`,
  `ProductwiseController::index`), and 10 resource routes declare a `store()` the controller lacks.
  See [08-routing.md](08-routing.md).
- `BROKEN` — Any authenticated dashboard user can reset any other dashboard user's password.
  See [13-security-findings.md](13-security-findings.md).
- `VERIFIED` — Spatie roles/permissions are defined but no route enforces them; authorization is
  UI-hiding only. See [11-authorization-rbac.md](11-authorization-rbac.md).
- `VERIFIED` — Shiprocket credentials are hardcoded in controller source. See
  [16-external-integrations.md](16-external-integrations.md).
- `BROKEN` — Unauthenticated `GET /api/test` writes a database row and dumps customer records.
  See [13-security-findings.md](13-security-findings.md).
- `VERIFIED` — Schema drift: 60 migration files cover a small fraction of the tables the models
  and queries use. See [05-database-schema.md](05-database-schema.md).
- `VERIFIED` — Test suite is the unmodified Laravel scaffold (4 files, no domain coverage).
  See [21-testing.md](21-testing.md).
